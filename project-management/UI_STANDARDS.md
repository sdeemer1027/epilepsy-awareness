# Purpose

This document defines the visual standards and reusable UI components used throughout the Epilepsy Support Platform.

The goal is to ensure consistency, accessibility, and maintainability across all interfaces.

---

# Design Principles

Every interface should be:

- Simple
- Consistent
- Accessible
- Responsive
- Calm and supportive
- Easy to learn
- Focused on the user's task

---

# Color System

## Primary

Used for primary actions and branding.

Examples:

- Main buttons
- Active navigation
- Links

---

## Secondary

Used for supporting interface elements.

---

## Success

Examples:

- Saved successfully
- Medication logged
- Registration completed

---

## Warning

Examples:

- Medication reminder
- Upcoming appointment
- Incomplete profile

---

## Danger

Examples:

- Validation errors
- Critical alerts
- Emergency information

---

## Information

Examples:

- Educational notices
- Tips
- General announcements

# Typography

Use a consistent typography scale.

Heading Levels

- H1
- H2
- H3
- H4

Body

- Large
- Standard
- Small

Caption

- Metadata
- Helper text

---

# Layout Grid

Desktop

12-column responsive grid.

Tablet

8-column grid.

Mobile

Single-column layout.

---

# Buttons

Primary Button

Used for the main action on a page.

Examples:

- Save
- Register
- Record Seizure

Secondary Button

Used for supporting actions.

Danger Button

Used only for destructive actions.

Examples:

- Delete
- Remove Access

Text Button

Used for low-priority actions.

---

# Forms

Every form should include:

- Labels
- Placeholder text (when appropriate)
- Helper text
- Required indicators
- Inline validation
- Accessible error messages

---

# Cards

Cards should be used for:

- Dashboard widgets
- Event summaries
- Article previews
- Medical summaries

---

# Tables

Tables should support:

- Sorting
- Filtering
- Pagination
- Responsive display
- Keyboard accessibility

---

# Alerts

Types

- Success
- Information
- Warning
- Error

Alerts should include:

- Clear message
- Appropriate icon
- Dismiss option (when appropriate)

---

# Badges

Examples

- Active
- Pending
- Archived
- Draft
- Published
- Cancelled

---

# Icons

Icons should always reinforce text.

Never rely on icons alone to communicate meaning.

---

# Navigation

Primary Navigation

Persistent sidebar (desktop).

Secondary Navigation

Tabs within modules.

Breadcrumbs

Displayed on all authenticated pages.

---

# Empty States

Every empty page should explain:

- Why it is empty.
- What the user can do next.
- A primary call-to-action.

Example:

"No seizure records yet."

Button:

Record First Seizure

---

# Loading States

Use:

- Skeleton loaders
- Progress indicators
- Accessible loading messages

Avoid blank screens.

---

# Error States

Errors should:

- Explain what happened.
- Explain how to recover.
- Avoid technical jargon.

---

# Accessibility Standards

Target compliance:

WCAG 2.2 AA

Requirements:

- Keyboard navigation
- Screen reader support
- High contrast
- Visible focus indicators
- Descriptive labels
- No color-only communication

---
